4. Components, explained

voice in Silero VAD

A 2 MB neural network that answers "is this speech?" every 32 ms.

  • Speech that stops for 0.6 s closes a segment, sent to Whisper while the student is still talking.
  • Mic ignored for 0.4 s after the robot speaks (its own echo).
  • Trailing silence is cut before Whisper, which otherwise invents words like "You".
  • Runs on onnxruntime directly: no PyTorch, light enough for the Pi.
coach/audio/vad.py

voice in Whisper, two models

OpenAI's multilingual recognizer on faster-whisper (C++ engine, int8 support).

  • Answers: accurate (small PC / base int8 Pi), word timestamps for pace. A hint prompt ("Umm, uh…") keeps filler words in. English + Tagalog only.
  • Commands: base int8, greedy, language given: about 1 s instead of about 7.5 s.
coach/asr/faster_whisper_backend.py · make_command_asr()

voice in Voice commands

  • "start / simulan", "yes / oo", "that's my answer / tapos na po", "stop the interview / itigil ang interview", "keep it / itago".
  • Fuzzy matching: "top the interview" still counts as "stop the interview".
  • "That's my answer" only counts at the end of what was said.
  • Consent "yes" must be clear; consent is never assumed.
coach/session/voice.py

voice out Piper + MMS-TTS

  • All robot lines and questions are made in advance into cache/questions/: a WAV plus JSON with subtitle cues (≤ 2 lines × 42 chars) and lip-sync levels (loudness every 30 ms → mouth 0–3).
  • Clips load in under 0.2 s; Piper speaks live English if needed.
  • 0.35 s of silence after each clip so Windows doesn't cut the last word.
  • Known limit: MMS Tagalog mispronounces English technical words.
offline/synth_questions.py · coach/tts/

language English or Filipino

  • Starts in English.
  • The student's first spoken reply decides once ("simulan" / "oo" = Filipino).
  • Locked for the whole interview; answers never switch it.
  • Filipino only if every Filipino clip exists, so it never mixes.
Session._set_lang() · staff override keys E / F

vision MediaPipe Face Landmarker

  • 478 face points (irises included) + 3D head rotation, in one pass per frame.
  • Presence, turn angle (eyes and arm), eye contact = yaw and pitch within ±15° and irises centered.
  • Eye-contact % per answer goes into the report.
coach/vision/face.py · gaze.py · loop.py

rules Delivery

  • Pace: words per minute from Whisper timings.
  • Long pauses: gaps ≥ 3 s between segments. Response delay before starting.
  • Fillers: um / uh / hmm always; ano / parang / like only next to a pause or repeated.
  • Each measure becomes a plain-language tip when out of range.
coach/delivery/

output Face page + report

  • SVG face with 7 expressions (none negative), eyes that follow, lip-sync, subtitles, small choice buttons under the face.
  • Live updates from Python over a WebSocket; Chromium kiosk on the Pi.
  • Report: printable report.html + report.json, saved only if the student keeps it.
coach/face/ · coach/session/report.py

5. How an answer gets its rubric score

Scoring v0: pretrained embeddings, no training (coach/scoring/score.py).

  1. Each rubric criterion has faculty example answers at levels 5, 3 and 1.
  2. The answer and every example become embedding vectors (multilingual-e5-small): numbers that capture meaning, so a Taglish answer can be compared with English examples.
  3. Cosine similarity measures how close the answer is to each level's examples.
  4. A softmax over the levels (temperature 0.02) gives a score from 1 to 5.
  5. The report stores which criterion and which example answer produced the score: the proposal's "traceable to an approved criterion".
  6. The correction tip is the faculty-written tip of the lowest-scoring criterion.
Next: scoring v1 (T3.1). A small ordinal classifier trained on the same features (coach/scoring/features.py) against real faculty ratings, target κ ≥ 0.60. It runs on the PC CPU, so no Colab is needed.

5b. The generative interviewer

In English sessions (interviewer.mode: generative, the default) the robot talks like a real interviewer with CpE/ECE knowledge instead of reading fixed questions. It runs locally on llama.cpp; nothing goes online.

slots Competency blueprint

samples/blueprint.json: one slot per rubric question says what the question must find out. The AI picks the wording; the answer is scored with that slot's rubric, so scoring stays valid and traceable.

memory Session memory

The student's first name (asked and confirmed after consent), topics, feelings and short facts from every answer. AI facts are kept only if the student really said those words. RAM only, cleared at the end.

knowledge CpE/ECE library

~48 short passages (microcontrollers, buses, circuits, signals, PCB…). The closest one keeps a technical question relevant. Unapproved sample: faculty review it (G0).

guard Guard v2

Rejects judging, "we / our", private topics, invented names, numbers or technical terms, and false "you mentioned…" claims. A rejected or late sentence is replaced by the approved line.

answer ends→"I see." / praise if a criterion ≥ 4→ ≤ 1 AI follow-up→next question written while the student answers→ guard check→ask it (or the rubric question)

6. The robot's reply to what the student said

The meaning of every reply comes from an approved line; in English sessions a local AI (Qwen2.5 on llama.cpp) rephrases it to refer to the student's words, as the proposal allows ("may rephrase or follow up only from approved items").

laughed? → "Haha!" + amused face (once)/else "I see."→ topics · feelings · rough score→choose 1 approved reply→ AI rephrases (English)→guard check→speak (or approved line)

Guardrails (guard.py): the AI's reply is rejected if it judges ("great", "wrong"…), drops the approved question, adds numbers or new facts, drops the topic, or speaks as the student ("our project"). A rejected or late (> 5 s) reply is replaced by the approved line. Topics come only from the approved glossary, so "ESB 32" is spoken as "ESP32". Filipino sessions use approved clips only. The report records every reply, its source and why it was chosen.

7. What runs at the same time

Main thread

Interview flow, mic reading, VAD, timing rules, robot speech playback.

Worker: accurate

Whisper (answer model) per segment, then the real score + delivery per answer, in order.

Worker: quick

Decisions the student waits for: "that's my answer" / "stop" checks and the follow-up choice, on the fast model. Never waits behind slow work.

Vision thread

Camera frames → MediaPipe → presence, gaze, eye contact (capped at the profile's fps).

Face server threads

HTTP for the page + WebSocket for live state; the last state is replayed if the page reloads.

⚠ Privacy before you upload anything. Colab runs on Google's servers. The proposal promises recordings stay on the device, and student voices and faces are personal data under the Data Privacy Act (RA 10173).
  • Fine on Colab: public datasets (Google FLEURS, Mozilla Common Voice Filipino), code, model files.
  • Student recordings: only if the signed consent form (T0.2) and your adviser / ethics committee allow cloud processing. Otherwise train on public data on Colab and do anything with student audio on the PC.
  • Never upload names; use anonymous codes.

12. Testing

  • pytest runs 100+ tests: each module with known test audio (Piper speaks sentences with known words), the face server, scoring order (good > mid > poor), full simulated interviews (tapped and spoken), language locking, timing rules, follow-ups, the generative interviewer (names, memory, guard v2, AI questions with fallback, praise, coaching, and a full simulated interview with the real model), and the "no PyTorch in coach/" check.
  • python -m eval.simulate_session --sessions 3 runs gate G1 with a simulated student (--generative for the AI interviewer).
  • python -m eval.interviewer_eval measures the AI interviewer: guard pass rate, personalization, latency.
  • Model-dependent tests skip themselves if models/ is empty.
